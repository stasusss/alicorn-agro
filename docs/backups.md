# Бекапи клієнтських даних

Покази, облікові записи, шлюзи, датчики й правила сповіщень лежать у Neon. Історія Neon (point-in-time restore) піднімає базу на момент усередині акаунта. Вона не переживає видалення проєкту Neon. Друга копія — щоденний `pg_dump`, зашифрований `age`, у бакеті Cloudflare R2.

## Що лежить у R2

Ключ: `backups/alicorn-YYYY-MM-DDTHH.dump.age` (година UTC).

Усередині: gzip custom-дампа Postgres (`pg_dump --format=custom`). Дамп містить хеші паролів і ключів шлюзів, тому в бакет і на диск потрапляє лише зашифрований файл.

Зберігаються найсвіжіший дамп кожного з останніх 30 днів і найранніший дамп від 1-го числа кожного з останніх 12 місяців. Решта ключів із цим префіксом видаляється після вдалого завантаження. Чужі ключі скрипт не чіпає.

## Секрети

Лише в GitHub Actions (і локально в `.env`, який не комітиться):

| Змінна | Навіщо |
| --- | --- |
| `DATABASE_URL` | прод Neon, з нього знімається дамп |
| `R2_ACCOUNT_ID`, `R2_ACCESS_KEY_ID`, `R2_SECRET_ACCESS_KEY`, `R2_BUCKET` | запис у R2 |
| `AGE_RECIPIENT` | публічний ключ `age1...` |
| `AGE_IDENTITY` або `AGE_IDENTITY_FILE` | секретний ключ, лише для відновлення |
| `RESTORE_DATABASE_URL` | порожня база, ніколи не прод |

`AGE_RECIPIENT` можна тримати поруч із дампом: без секретного ключа файл не читається. Секретний ключ зберігає людина, яка відновлює прод. Його немає в репозиторії, у Vercel і в R2. Якщо ключ загублено, старі дампи не розшифрувати — зніміть новий і покладіть копію ключа в менеджер паролів.

Ключ створюється один раз: `age-keygen -o identity.txt`. Рядок `public key:` — це `AGE_RECIPIENT`.

## Розклад

Workflow `.github/workflows/backup.yml` щодня о 02:00 UTC і вручну через `workflow_dispatch`. Після дампа скрипт перевіряє, що файл ненульовий і що `pg_restore --list` бачить таблиці `organizations`, `users`, `sensors`, `readings`.

Локально, без завантаження:

```bash
AGE_RECIPIENT=age1... DATABASE_URL=postgresql://... npm run db:backup -- --out ./backups --skip-upload
```

## Відновлення

1. У Neon увімкніть історію на платному плані. Для швидкого відкату створіть гілку на потрібний час і перевірте кількість рядків у `readings`, перш ніж перемикати прод.
2. Для копії поза Neon: порожня база в `RESTORE_DATABASE_URL` (інший проєкт або гілка, не той самий URL, що `DATABASE_URL` — скрипт відмовиться).
3. Розшифрування й заливка:

```bash
RESTORE_DATABASE_URL=postgresql://.../empty \
AGE_IDENTITY_FILE=./identity.txt \
npm run db:restore -- --file ./backups/alicorn-2026-10-19T02.dump.age
```

Або `--r2-key backups/alicorn-2026-10-19T02.dump.age`, якщо в середовищі є ключі R2.

4. Звірте `select count(*) from readings` з очікуваним і лише тоді міняйте `DATABASE_URL` застосунку.

Один раз проженіть цей сценарій на гілці Neon, не на проді, і переконайтесь, що секретний ключ `age` відкриває останній об’єкт у R2.

## Видалення датчика

`readings.sensor_id` більше не каскадом стирає покази. На вже створеній базі Neon один раз:

```bash
npm run db:restrict-readings
```

Локальний PGlite отримує те саме обмеження під час відкриття бази. Датчик вимикають прапорцем `active`, а не `DELETE`.

## Якщо прод уже недоступний

Будить той, у кого є секретний ключ `age`, доступ до R2 і право створити базу Neon. Репозиторій сам дані не містить.
